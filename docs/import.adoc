== Imports

`eirctl` can merge configuration files from local and remote sources.

[source,yaml]
----
# yaml-language-server: $schema=https://raw.githubusercontent.com/Ensono/eirctl/refs/heads/main/schemas/schema_v1.json

import:
  - https://raw.githubusercontent.com/Ensono/eirctl/v0.11.8/shared/terraform/eirctl.yaml
  - ./local/relative/to/cli/eirctl.yaml
  - /absolute/path/eirctl.yaml
----

=== HTTPS

For HTTPS imports, ensure that the URL returns the configuration contents directly. On GitHub, use a `raw.githubusercontent.com` URL.
Remote HTTP imports and HTTPS redirects to HTTP are rejected. Use HTTPS with a trusted certificate or import a local file instead.

[NOTE]
====
Use the `.yaml` extension where possible.
====

=== Legacy Git imports

Git imports are disabled by default because the bundled Git client uses
collision-detecting SHA-1 object identifiers. Prefer a direct HTTPS import
with a SHA-256 pin, or a local filesystem import from a trusted checkout.
If you still need `git::` imports, set `EIRCTL_ALLOW_LEGACY_GIT=true` in the
operator's environment. This applies to Git over SSH, HTTPS, and local Git
repositories, including cached imports. Imported YAML cannot opt in.
Unset the variable to disable the importer again.

When using the legacy importer, use authenticated SSH or HTTPS for remote
repositories and add a SHA-256 pin obtained independently of the import.
Collision detection mitigates known attacks but does not make Git's SHA-1
object identifiers a strong integrity guarantee.

[IMPORTANT]
====
The import value must match `^git::(ssh|https|file)://(.+?)//([^?]+)(?:\?ref=([^&]+))?$`.
====

Supported Git protocols are:

* SSH
* HTTPS
* FILE

[TIP]
====
An optional `ref` can identify a branch, tag, or commit SHA.
====

[IMPORTANT]
====
Set `GIT_SSH_PASSPHRASE` when the selected SSH key is encrypted with a passphrase. This setting is global: once set, it is used across all organizations and repositories.
Encrypted identities must use the OpenSSH private-key format with AES-256-CTR. Replace weak keys and legacy PEM or CBC-encrypted identities before upgrading.
====

See <<_ssh_server_trust,SSH server trust>> for key requirements and temporary compatibility settings.

=== Integrity

Use the object form with `hash: sha256:<hex-digest>` to pin either an imported
configuration or a file with `dest`. Obtain the digest through a trusted channel
independent of the import. `eirctl` verifies fetched and cached bytes before
using them and rejects a mismatch. After a mismatch, investigate the source
before removing the affected cache entry or updating the expected digest.

A Git `ref` selects a revision but does not replace the SHA-256 pin. Git
repositories using the conventional object format still use collision-detecting
SHA-1 for object IDs; this mitigates known collision techniques but does not
provide SHA-256 integrity.

=== Filesystem

Filesystem imports support relative and absolute paths.

=== Command line

`eirctl run` accepts a repeatable `--import` flag to bring in additional config files at execution time, without editing the project's config file:

[source,bash]
----
eirctl run task1 --import ./local/context-overrides.yaml
eirctl run pipeline pipeline1 --import ./local/context-overrides.yaml --import ./local/extra-tasks.yaml
----

This is useful when working with new or unverified contexts during development, avoiding the risk of accidentally committing them to the tracked config file.

[IMPORTANT]
====
Unlike the `import:` directive in a config file, which errors on a name clash, entries supplied via `--import` on the command line take precedence over any existing tasks, pipelines, or contexts with the same name.
====
